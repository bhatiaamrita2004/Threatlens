ThreatLens is a security event monitoring and alert triage platform. It generates or ingests security events, detects suspicious activity with rules and anomaly scoring, groups findings into alerts and incidents, and lets analysts review each alert and record a verdict.

It is a portfolio project built phase by phase from a 17-phase blueprint. It runs on synthetic data only.

## Features

- **Detection:** rules for repeated failed logins, port scans, event bursts and privilege changes
- **Behavioural baselines:** per-user comparison of each time window against normal activity
- **Anomaly detection:** Isolation Forest and Local Outlier Factor models, compared against the rules
- **Scoring:** a 0 to 100 score, severity bands, and a written explanation for every alert
- **Incidents:** related alerts grouped into incidents
- **Analyst workflow:** verdicts (true positive, false positive, needs review) update alert status and keep a feedback history
- **MITRE ATT&CK:** each alert is mapped to its technique
- **Dashboard:** alerts, evidence timelines, incidents, and live refresh

## Quick start (Docker)

Requirements: Docker Desktop.

```bash
cp .env.example .env
# edit .env and set THREATLENS_JWT_SECRET to a long random value
docker compose up --build
```

| Service | Address |
|---|---|
| Dashboard | http://localhost:3000 |
| Backend health | http://localhost:8080/actuator/health |
| Backend API docs | http://localhost:8080/swagger-ui.html |
| ML service docs | http://localhost:8000/docs |

Log in as `analyst` / `analyst123` (demo account). The demo accounts are created when `THREATLENS_SEED_DEMO_USERS=true`.

The Docker setup runs PostgreSQL, Redis, Kafka and the three services. OpenSearch is left out of Compose for now, and the backend runs with `THREATLENS_OPENSEARCH_ENABLED=false`.

To load the sample detections into a running backend:

```bash
python3 detection-engine/publish_detections.py --username admin --password admin123
```

## Running without Docker

1. Start PostgreSQL 16 with database `threatlens`, user `threatlens`, password `threatlens`.
2. Start Kafka on `localhost:9092` (optional).
3. Start the backend:
   ```bash
   cd backend && mvn spring-boot:run
   ```
4. Start the dashboard:
   ```bash
   cd frontend && npm install && npm run dev
   ```
5. Optional, the ML service:
   ```bash
   pip install -r ml-service/requirements.txt
   uvicorn app.main:app --app-dir ml-service --reload
   ```

## Tests

```bash
# Python: rules, scoring, baselines, features, ML, pipeline, publisher
python3 -m unittest discover -s detection-engine/tests -v

# ML service API tests
python3 -m pytest ml-service/tests -q

# Java: API tests, Mockito unit tests, health endpoint
cd backend && mvn clean test
```

The live backend tests in `detection-engine/tests/test_backend_live.py` run only when the backend is up. They skip themselves otherwise.

Full details are in [docs/testing-and-limitations.md](docs/testing-and-limitations.md).

## Results (synthetic data)

- **Rules:** precision 1.00, recall 0.79, F1 0.88 across 188 labelled time windows. They catch brute-force and port-scan windows but not unusual logins.
- **Isolation Forest:** precision 1.00, recall 0.74, F1 0.85. No false alarms on normal windows.
- **Pipeline:** 500 events ingested through Kafka with 0 failures. The attack scenarios produce 4 alerts grouped into 1 CRITICAL incident.

These numbers come from data generated by the same simulator used to design the attacks. They show the rules and model work on the designed patterns, not on real traffic.

## Known limitations

- Synthetic data only. The results don't reflect real attack or false-positive rates.
- Unusual logins are not detected by any rule. The gap is recorded as an expected test failure.
- Login rate limiting is per username, not per IP, and fails open if Redis returns no value.
- OpenSearch is best-effort. Indexing failures are logged, not raised.
- Tokens cannot be revoked before they expire (60 minutes by default).
- The dashboard uses polling (every 5 to 10 seconds), not push updates.
- Demo accounts are on by default. Turn them off with `THREATLENS_SEED_DEMO_USERS=false` before sharing the system.
