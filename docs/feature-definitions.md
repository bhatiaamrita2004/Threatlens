# Feature definitions

Generated by `detection-engine/feature_engineering.py`.

One row = one entity (a user, or a source IP) in one 5-minute UTC window.

| Column | Meaning |
|---|---|
| `event_count` | All events for this entity in the window. |
| `failed_login_count` | LOGIN_FAILED events in the window. |
| `login_success_count` | LOGIN_SUCCESS events in the window. |
| `failure_ratio` | failed_login_count / (failed_login_count + login_success_count). 0.0 when there are no login events. |
| `offhours_login_count` | Login events (success or failure) between 00:00 and 05:59 UTC. |
| `avg_login_hour` | Mean UTC hour of the login events in the window. Empty when there are no logins. A plain mean does not handle midnight wrap-around, so treat it as a rough signal. |
| `connection_count` | CONNECTION_ATTEMPT events in the window. |
| `unique_ports` | Distinct destination_port values in the window. Null ports are ignored. |
| `unique_source_ips` | Distinct source_ip values in the window. For user rows, this counts the addresses the user logged in from. |
| `unique_locations` | Distinct location labels in the window. |
| `request_count` | API_REQUEST events in the window. |
| `privilege_change_count` | PRIVILEGE_CHANGE events in the window. |
| `restricted_access_count` | RESOURCE_ACCESS events with metadata.restricted = true. The current synthetic data has none, so this is 0 until such events are generated. |

Key columns: `entity_type`, `entity_id`, `window_start`.

Label columns (evaluation only, never features): `scenario` lists the synthetic scenario labels in the window, and `label` is 1 if any event in it is synthetic attack data.
